# Requirements Analysis
Read the supplied requirement and relevant repository context. Do not invent missing business facts.
Return concise sections: Status (READY or NEEDS_INPUT), Functional Requirements, Non-Functional Requirements, Ambiguities, Clarification Questions, Acceptance Criteria.
For brownfield work, preserve backward compatibility unless the requirement explicitly changes it.
